# Architectural decisions

1. **Three.js over Babylon.js.** We need direct scene control, instancing and procedural geometry, not a full engine. Only one 3D library is used.
2. **Component-bag ECS instead of an ECS library.** Entities are plain objects with optional components. They are trivially serializable and fast enough for hundreds of agents. Archetype storage can be revisited if profiling demands it.
3. **Grid navigation (2 m cells) instead of a road graph for the MVP.** The procedural city is small (420 × 352 m, about 37k cells), so A* is cheap, and the same grid handles walls, gates and local movement. A road graph layer for long trips is planned with real maps.
4. **Shared distance field for hordes** instead of per-agent A*. Walls have a cost proportional to their HP, so hordes pick a breach point emergently, with no cheating spawns inside the base. The field is recomputed only when the grid version changes. Full recomputation is about 2 ms today. Region-local invalidation is a planned optimization for large maps.
5. **Global stock with physical storage nodes.** Each storage building holds its own stock, and workers physically carry materials from storage to sites. The HUD shows totals. Tower guards are resupplied abstractly.
6. **Renderer reads simulation state directly** (read-only) instead of copying snapshots. This is simpler and allocation-free. The command queue still enforces one-way mutation.
7. **No Web Worker yet.** The simulation costs well under 1 ms per frame — measured at 0.045 ms with a city, a squad and the task systems on a 25 entity map, and the render is the whole frame at 320 ms in a software renderer (see [PERF.md](PERF.md)). The core is DOM-free, so moving it to a worker later is mechanical, but it would free four hundredths of a millisecond and buy nothing.
8. **Time freezes while an event card is open or before a base is chosen**, so the player is never punished for reading.
9. **Units are drawn at life size.** They were drawn 1.9× for legibility at the strategic zoom, and that held while the units were capsules nobody compared with anything. Once the models read as people it stopped holding: a survivor stood 3.65 m tall against a 1.41 m car and a 3.2 m door module, so the city looked built for dwarves. The scale is now 1.0 and the default camera distance came down from 170 m to 120 m, which buys back most of the pixels the scale gave up — a unit is about 19 px tall at the map zoom instead of 25. Measured in a capture at 14 m: the shirt band is 70 px, against 64 px predicted for a 1.92 m figure, where the 1.9× version measured about 122 px.
10. **Real maps are imported in the browser, not by an offline tool.** The game is a static site on GitHub Pages, so the player's browser asks Overpass for one small area (400 to 600 m square) when they start, and keeps the answer in IndexedDB. One request per new game is light use of the public servers; nothing is fetched in bulk. Search uses Nominatim only on an explicit search.
11. **One building path for both map kinds.** Procedural rectangles and real footprints go through the same extruded-outline renderer. The grid stamps footprints by cell center; door, perimeter and window-fire code use the outline when there is one and the rectangle otherwise, so procedural balance is unchanged.
12. **Every real map gets a supermarket and a police station.** If the area has none, a mid-sized shop, office or warehouse near the center is promoted, because food and ammo depend on them.
13. **Pages from the `gh-pages` branch, with PR previews.** GitHub Pages serves a single site, so `main` is published to the branch root and each pull request to `pr-preview/pr-<number>/` in the same branch (`rossjrw/pr-preview-action`). The main deploy keeps that folder, and a closed PR removes its own. A fork cannot push to `gh-pages`, so it only uploads the built site; `pages-preview-fork.yml` on `main` publishes that artifact after the pull request head matches the run, and never checks out the fork.
14. **Commands are drained while time is frozen.** A pending event, a manual pause or a defeat stops the clock, but the command queue is still applied. Resolving an event is a command, so waiting for the next tick would deadlock the modal; applying commands without advancing the clock keeps the UI responsive and preserves determinism. Commands are discarded after defeat.
15. **The debug controller is development-only.** `window.__afterfall` is assigned only under Vite's `import.meta.env.DEV`, so the production bundle does not expose a mutable simulation handle. The Playwright suite runs against the dev server and keeps using the hook; CI rejects the string in `apps/web/dist`.
16. **Saves are validated before load.** `deserialize` rejects newer versions, malformed internals, OSM saves without their embedded map and states whose building count does not match the map. Imported maps must keep the same building order they had when saved, and migrations are added per version bump.
17. **Quality gates run in CI.** ESLint and Prettier check the code, Vitest enforces V8 coverage thresholds, `pnpm audit` blocks high or critical advisories, and a WebKit smoke test checks the shell beyond Chromium. Firefox smoke is available locally; the hosted runner lacks a Firefox WebGL context without extra OS packages.
18. **The Linux desktop build is a snap of the web game.** `apps/desktop` is an Electron shell that serves `apps/web/dist` from `app://game/` and adds only a quit bridge. The Snap Store builds `snap/snapcraft.yaml` on `main` and releases it to edge. CI builds the same file, installs it and runs `--smoke`, which starts a generated city and checks the HUD, local storage and the quit bridge. The smoke does not use `window.__afterfall`. Real-map downloads are allowed to reach Overpass and Nominatim; the rest of the game stays offline.
19. **Sound is a separate package driven by the simulation, never by the UI.** `@afterfall/audio` keeps the sound table and the event mapping pure (no DOM, no Three), and its director reads `sim.fx` and `sim.state.alerts`, so combat, construction and night alarms make noise without any component wiring sound by hand. The browser only unlocks an `AudioContext` on the first gesture and feeds the director once per frame. Voices are capped per sound and globally, and a backlog larger than a couple of dozen events is dropped instead of dumped, so a paused tab never returns in a burst of noise. Positional sound is approximated from the screen centre in world space (pan ignores camera rotation for now). Volume and mute live in the UI store and are persisted with the language (`afterfall.volume`, `afterfall.muted`); the director follows the store instead of the UI calling it. Day and night each get a looping ambience bed, crossfaded over 1.2 s when the clock changes half of the day.
20. **Impact effects are particles instanced from the same events as the sound.** `VfxSystem` reads `sim.fx` and turns each hit, death, melee, shot and build into a short-lived burst of billboarded quads in one `InstancedMesh` (one draw call; the particle is a radial gradient drawn to a canvas). Additive blending doubles as the fade — the instance colour runs to black as the particle ages, so no per-particle material or alpha sorting is needed. Physics uses a clamped step, but lifetime consumes the real delta, so returning from a background tab never leaves ghosts on screen.
21. **Each event has its own flipbook, and dull ones blend normally.** On top of the particles, a pool of 24 billboarded quads plays a flipbook per event: a muzzle flash for shots, a cloud for deaths, dust for work ticks, a claw slash for infected strikes, a ground ring for gunfire noise, a rubble cloud for a fallen structure, and the original spark for hits. Flash and spark are additive; the clouds are not, because adding a dark or dull colour adds nothing, so they use normal blending, fade by opacity and replace the particles of their event (twenty additive red particles glowed like neon over the death cloud). The strike is additive like the flash, but drops its particles as well: eight pale blobs buried the claw streaks, and every other strike is mirrored so a sustained attack does not stamp one slash. The strike's sheet was rebuilt once it was measured: with one camera and a paused simulation, the three thin strokes it started with owned 0.04% of the frame at the combat zoom and 0.01% at the default one — the least of the six atlas effects at both distances, on the event the player sees on every strike — so the sheet is now four thick staggered claws over an impact flash and embers, and it owns 0.21% and 0.03% with more than twice the contrast. The muzzle flash was measured the same way and rebuilt for the same reason: on every shot it owned 0.07% of the frame at the combat zoom, last of the seven, so its sheet went from two orange stars over a small core to a white-hot core with a six-point burst, a nine-point flare and a growing shock ring — six frames instead of four, and 0.16% with contrast 136. The `noise` event was declared but never emitted; `emitNoise` now publishes it with its radius (`Fx.r`), so the ring shows exactly how far a shot pulls infected. It plays no sound, because its shot already does, and without its sheet it draws nothing rather than a spark on every shot. A destroyed structure used to emit `death`, so a wall fell in a puff of blood; it now emits its own `collapse`, which is silent in the mapping because `alert.structureDestroyed` already plays. The pool is shared, and each slot sets its blending per burst, which is render state and recompiles nothing. Work ticks fire every 15 ticks per worker on any task, so their dust is capped at six alive. Every sheet loads asynchronously, and an event whose sheet has not arrived plays the spark.
22. **Facades are baked from geometry and multiplied under the building tint.** Each style is a 12.8 m module (4 bays by 4 floors of 3.2 m, the simulation's floor height) built in Blender with real recesses, frames, sills and boards, over 3 by 3 copies so shadows cross the tile edge, and rendered head-on in Cycles; grime is noise sampled on a torus, so the tile has no seam. The maps are kept near neutral because the vertex colour still carries game information (type, explored, looted, function, resource and danger overlays), and each style gets a gain that brings its mean up to the old concrete map, or the dark roofs went black at night. Night windows are one shared emissive mask per style gated by a per-vertex `glow`, set only on settlement buildings: the mask makes the city look inhabited, the gate keeps the rule that light means "ours". The art budget moved from 1 MB to 8 MB of streamed files because the maps load after the first frame and never delay a game's start.
23. **One infected model, three kinds, and only the skin is tinted.** `tools/blender/infected.py` bakes a single hunched silhouette (504 triangles, three materials) that the renderer instances in place of the capsule the infected had since phase 5; the capsule stays in the scene, hidden once the GLB lands, so a missing or broken file costs a silhouette and nothing else. The kinds are not modelled because the content table already separates them by `scale` and `color`, and a second and third mesh would be three more draw calls per part for a difference the player reads from size, speed and hue. The instance colour is written only on the `skin` part: giving every part an instance colour is the bug that turned the survivor kit's heads black, and here it would also multiply the emissive eyes to nothing. The eyes are the one emissive surface, which is what keeps a horde visible at night without a bloom pass. Measured in the headless renderer at 14 m: the model covers 5.6% of the frame where the capsule did, the frame is otherwise pixel-identical, and the whole horde costs three draw calls against the capsule's one. With 262 infected on screen the frame took 785 ms against the capsule's 923 ms over 20 frames each — inside the software renderer's own ±2× swing, so that is not a speed claim, only the absence of a regression. No separate silhouette per kind until a playtest says the kinds are not readable.
24. **Units walk on six baked poses, and the phase comes from distance travelled.** `InstancedMesh` cannot carry a skeleton, and one `SkinnedMesh` per unit would cost a draw call per survivor and another per infected, so the cycle is baked into the model instead: `tools/blender/survivors.py` and `infected.py` export `pose0`…`pose6`: six gait keys plus a standing pose, and the renderer keeps one instanced mesh per pose and material — 21 meshes per model, and only the poses that hold units this frame draw. The standing pose is not optional: with only the cycle, an idle unit froze on the contact pose and stood in a full lunge, 0.947 m deep against 0.491 m standing, which is what made a squad around the headquarters look wrong. A unit switches to it after eight frames without movement, which bridges the gap between 20 ms simulation ticks at 60 fps without flickering the pose. The phase is advanced by the distance a unit actually covered, not by a clock: a time-driven phase slides the feet as soon as the simulation speed or the frame rate changes, which is the exact artefact the animation is meant to remove, and a unit that has not moved stays on the contact pose so nobody marches on the spot. A jump longer than a stride in one frame is treated as a teleport and does not advance the phase. The first version drove the six poses with `sin(2πi/6)` and produced two distinct stances out of six, because `sin(60°) == sin(120°)`; the cycle is therefore an explicit table, and both exporters print each pose's foot positions and its maximum vertex distance from pose 0 so a future edit cannot quietly collapse the gait again. Measured 52 draw calls with the squad standing at the headquarters, 75 with thirty-three infected spread over the seven poses. The models grew from 21 KB to 123 KB (survivor) and 28 KB to 157 KB (infected).
25. **Research buys capabilities, and the laboratory is not gated behind them.** Twelve nodes in four branches, each one a capability the player can describe in a sentence (cheaper meals, a deeper well, a bigger pack, faster repairs, a workshop that doubles ammo, more loot per search, a deeper ammo reserve, better aim, floodlit towers, a one-dose serum, a faster lab, the cure). Points come from searching schools, hospitals, police stations, offices and pharmacies, and a standing **laboratory** earns them every game hour. The first version put the lab itself behind a seven-point node, which is a deadlock: the only reliable source of research was the thing the research was supposed to unlock, so a settlement that had not searched the right buildings could never start. The lab is therefore a plain conversion, and the `lab` node upgrades its output by half. Research is kept in `state.research` rather than in the stock: it has no weight, it is not hauled, and it cannot be lost with a warehouse. The cure costs 12 medicine and 12 research and then advances one dawn at a time while its lab stands — the endgame is a building the player chose to defend, not a timer, and losing it pauses the project instead of failing the campaign. The campaign runs twelve nights because that is where the measured curve still lets a walled settlement hold; the cure is the intended ending and surviving is the fallback. Measured: the scripted fort player wins 3 of 10 seeds with research and 2 of 10 without, which is inside the noise of ten seeds and is recorded as unresolved, not as a gain (see `docs/BALANCE.md`).

26. **Structures are modelled per kind and instanced per material.** The five built structures shared one box scaled by `STRUCTURES[kind]`, so a tower and a wall differed only in height and hue. `tools/blender/structures.py` authors each one to the footprint the simulation already uses, and the renderer keeps one `InstancedMesh` per material per kind, which costs fifteen draw calls at most and none for a kind that is not on the map. Two rules came out of it: metalness stays at 0.15 because three.js has no environment map here and anything metallic renders black, and walls and gates read their neighbours in the navigation grid to decide the quarter turn (`axialYaw` in `structureLayout.ts`), because a piece drawn across its own line reads as a row of slabs with gaps, and a gate drawn sideways is worse than the box it replaced. The construction ghost uses the same axis and the piece's own thickness, so what is being raised is legible before it exists. The old box is kept as the fallback and as the blueprint ghost: a missing GLB costs a silhouette, never the game.

27. **Wear is one merged mesh per map, and state reaches the street through it.** The city had clean asphalt, no debris and buildings that only changed colour when looted. Three layers close that gap without a texture per building: street wear (cracks, patches, oil, rubble, weeds through the kerb joints, drifted litter) generated as an 8-tile atlas by `tools/make-decals.ts` and merged into a single geometry with per-vertex UVs, so a map carries three thousand pieces of wear in one draw call; a building's state (picked clean, or taken over) which drives the tint, the debris at the doorstep and the sweep of it, rebuilt only when a signature of the settlement changes; and a flag on the roof of every building the survivors hold, in the colour of what it is for. Three things had to be got wrong first. The decals were wound clockwise, so the computed normal pointed down and backface culling ate the entire layer — the fix is pinned by a test that reads the normal back. The flag first hung at the foot of the wall, where a building swallows its own flag, and then edge-on to the street, where it was four pixels of nothing; it now stands above the roof edge, facing the street. And the settlement light sat at 6 m over a 3.8 m roof, turning that roof into a white plate at night. The prop kit grew a container, a pallet of crates and an ambulance, chosen by the block's zone rather than by a global dice roll, and the prop hash took the side of the block as an input after all four sides were found carrying the same objects.

28. **Reachability is answered before A\* starts.** A settlement that walls itself in makes a large share of destinations unreachable, and A* answered "no" by expanding the whole grid — once per unit, on every retry. A CPU profile of one campaign seed put 44% of the time in `findPath`, 41% in the binary heap it pops, and 8.5% in `passableIndex`. `NavGrid` therefore keeps connected components of its passable cells, one array per agent because survivors may cross a gate and infected may not, rebuilt lazily when the grid version changes; `findPath` compares the two components first and returns in constant time when they differ. The flood fill uses the same no-corner-cutting rule as the search, so it cannot disagree with it, and a unit test pins that a rejected pair really is unreachable and that a gate splits the two agents. The same seed went from 400 s to 13 s, which is what makes a sixty-seed balance arm practical.

29. **The campaign bot plays a plan, not a chain of ifs.** Three bugs had made the scripted player look strategy-less: the workshop was requested on the building the shelter had just taken (a conversion on a building with a task is refused silently, and the bot believed it had one for twelve days); a strict `if/else` chain meant "no searched building for a shelter yet" also skipped the towers; and `hp > 0` filtered out every candidate, because an unconverted building has `hp: 0` and `maxHp: 0` until a function gives it one. It now takes one structural decision per game hour, each step independent so a blocked one does not starve the rest, pays for what it queues, and lowers `keepAmmo` to 20 while a metal-hungry structure is still owed. The wall ring stays where it was — one blueprint two minutes in — because a version that placed it in affordable slabs lost every seed of ten: the blueprint is a queue that fills as wood arrives, so starving it buys nothing and delays the wall the first night needs. Measured over twelve nights and sixty seeds: 24 wins with the research tree and 25 without, every research win a cure and every plain win a survival, so the tree buys the ending rather than the survival.

30. **Task priority is a player lever, so it gets a drawer.** The assignment loop already sorted tasks by `priority` and the `setTaskPriority` command already existed, but nothing in the interface could change it, which made the ordering a designer's decision the player could not see. The bottom bar gains a Tasks drawer listing every task in the order workers take them, with the status, the crew and two arrows that move the priority by ten inside 0–100. It is the one panel that explains why a worker is on the farm while the wall sits half-built.

31. **Storage is a place, and a full store refuses the harvest.** Before this, every deposit went to the nearest store and whatever did not fit was dropped without a word: on seed 2 the headquarters reached 600 of 600 on day 8 and spent the rest of the campaign throwing its own harvest away, which the ledger could not show because `produce` never looked at what `deposit` returned. Production now counts what a full store refused into `stats.wasted` and `econ.wasted`, and raises `alert.storageFull` — the one piece of feedback that makes converting a building into a warehouse a decision rather than decoration. The ledger panel gained the column that shows it. The bot converts one warehouse once the headquarters passes 85%, which on that seed doubles the food it keeps (135 at day 7 instead of 292 then wasted, 1,103 by day 11). Hauling is the second half: a `haul` task carries the excess of a store above `policies.haulAbove` (90% by default) into one with room, in batches of 40, at the lowest priority in the queue so it never takes a hand from a wall. It fetches from its own source rather than the nearest store, and it deposits into the destination's shelves rather than onto its doorstep. One haul exists at a time; with two stores both full there is nowhere to haul to, and the answer is another warehouse, not another task.

32. **Clearing a spatial hash is a counter, not a sweep.** The hash kept every bucket it had ever created and `clear()` walked all of them, twice per tick, because buckets are never removed. That is fine for a few hundred agents in one skirmish and fatal for a twelve-night campaign: the map fills with the cells anything has passed through, and clearing them cost more than the queries the hash exists to answer — 44% of a CPU profile at day nine with twenty-eight survivors. Clearing is now a generation bump: a bucket from an older generation is treated as empty by `query` and claimed on its next `insert`, so `clear()` is an increment and the cost of a bucket is paid once, when it is used. The slow seed went from 54 s to 23 s, and a profile afterwards is flat — no function above 7.5% — which is the signal that the next win is structural (a worker thread, LOD, chunk streaming) rather than local.

33. **A large city could not be built at all, and streaming is deferred on measurement.** The roadmap carried "chunk streaming and LOD for large imported cities" as a performance item. Before designing either, the cost of a large map was measured, and the answer was not a cost: `BuildingBatch` concatenated its vertex groups with `push(...array)`, and spreading a few hundred thousand numbers as call arguments overflows the stack. Six blocks of city worked; ten blocks — 435 buildings, 43k triangles, smaller than a real imported neighbourhood — threw `RangeError: Maximum call stack size exceeded` inside the constructor. The merge now uses typed arrays and `set` with a running offset, with the `owner` array moving in triangles while the vertex arrays move in vertices. Measured after the fix, eighteen blocks by eighteen: 1,553 buildings, 845 ms to build on load, 19 draw calls, 132,884 triangles, 4.8 ms per frame under SwiftShader. That is a 1.2 km square with more buildings than the importer accepts (it stays under 600 m), and the draw-call count and frame time are flat from six blocks to eighteen. Streaming and LOD exist to bound a cost that is not there; what would justify them is a map an order of magnitude larger than the importer allows, or a GPU measurement this project still does not have.

34. **An imported map is a city, not a lawn.** The ground of every map was the grass map, which is right for a generated city — blocks with sidewalks, grass between them — and wrong for an imported one, which has streets and building footprints and nothing else. A dense neighbourhood therefore rendered as buildings standing on a lawn with thin paved ribbons along the roads, which is what the first playtest video showed. `buildCityGround` now reports whether the map is imported (`blocksX === 0`, the value `cityFromOverpass` writes) and shades its base with the concrete map under a neutral tint; parks keep their grass polygons. The same function used to crash outright on a map with no roads at all, because `mergeGeometries([])` reads `geometries[0].index` without checking — guarded now, and pinned by a test that builds a map with no roads.

35. **A sidewalk sits beside a road, never under it.** Imported streets were drawn as a road ribbon with a wider sidewalk ribbon underneath, five millimetres apart. That is invisible up close and unmaintainable at distance: the two surfaces are coplanar within the depth buffer's precision, so the light ribbon won alternating stripes across the asphalt — regular white dashes on the road that appeared and disappeared as the camera moved, which is what the second playtest video showed. Raising the road and biasing its depth helped, but the overlap was the defect: the sidewalk is now built as two strips beside the carriageway, and a test asserts that no sidewalk vertex falls inside the road's half-width. The base of an imported map has been paved since decision 34, so the strip is a light edge, not the only ground the player sees.

36. **A paved base has to be darker than its sidewalk.** Decision 34 paved the base of imported maps and got the material right but the value wrong: the tint was as light as the sidewalk, so every open lot read as pavement and a building beside a street looked like a building on top of it — which is exactly how the third playtest report phrased it ("os prédios estão sendo construídos até em cima da rua"). Measured before changing anything: on a live São Paulo import, 13 of 238 buildings touch a road corridor, none with more than 10% of its area inside one, and exactly one building sits inside another (a tower over its annex, which is real architecture, not a bug) — so the data was not putting buildings on the road. The base is now clearly darker than the sidewalk, and a test pins the relationship rather than the literal colour: the base's luminance must stay under three quarters of the sidewalk's, so a future tint cannot turn the city back into a plaza.

37. **A building that OSM draws twice is imported once, and a footprint on a street is not a building.** Two guards now run before anything is stamped. The first drops the smaller of a nested pair — OSM maps a tower and its annex, or a building and its part, as separate ways, and both were rendered, so the smaller volume's walls cut through the larger one's roof and out over the road; a test asserts the invariant (no footprint sits entirely inside a larger one) rather than a particular pair. The second drops a building whose footprint is more than 40% inside a street corridor: keep an overhang over the sidewalk, because that is what dense cities look like, but a building standing on the carriageway swallows the road the survivors walk on. Neither guard fires on the São Paulo Sé import (191 of 191 buildings survive), which is why they are guards and not a fix — and why `?feet=1` now outlines every footprint on the ground. A screenshot cannot say whether a wall covering the street belongs to a footprint covering the street, because from a low camera a tall facade hides the road behind it; the overlay answers it in the frame. It is rebuilt with every city: it lives in the scene, not in the city group, so the first version survived a new game and drew the old map's footprints over the new one's empty lots.

38. **A street is as wide as OSM says it is, and a footprint stops at the kerb.** The ribbon used to take its width from a table by road class — every residential street eight metres, every primary twelve — and in a dense centre that was metres wider than the street, so the asphalt ran into the lots and a footprint mapped exactly where OSM puts it read as a building standing on the road. That is the fifth playtest report, and the yellow overlay was what proved it: the outline sat at the wall's base, and the wall's base sat on asphalt. Width now comes from the `width` tag, then from `lanes`, then from the class; on a live Sé import that is 4.2 m to 20.2 m instead of a fixed table. And a footprint that still reaches into a carriageway is pulled back to the kerb — vertices pushed to the corridor edge, which is cheaper than clipping two polygons and keeps the shape — with a footprint that would lose more than 40% of itself dropped instead of mangled. A test walks every footprint vertex against every road segment and asserts none falls inside.

39. **The shadow camera is sized by the camera, not by the settlement.** The sun's shadow box was a fixed 320 m square that followed the camera target. At play zoom an RTS camera sees more than that, so the far half of the screen fell outside the box and buildings were lit on one side and unlit on the other — a straight edge across the city, which is the sixth playtest report. The box is now `clamp(distance × 1.15, 90, 340)`, rebuilt only when that value changes, and it still follows the target so the resolution is spent where the player is looking. The cap is deliberate: the fog closes at 620 m, and a bigger box at 2048² would smear every shadow into mush. A test drives the camera to both ends and asserts the box lands at the floor and the cap.

40. **A landmark is drawn as itself, not as the square around its feet.** OSM maps the Eiffel Tower as one way tagged `building=tower` with `height=330`, and its footprint is the square enclosing the four legs: extruded like a building it became the hall between them, six floors tall under a flat roof, which is the seventh playtest report ("não conseguiu projetar a torre eiffel muito bem"). Two changes. The twenty-floor cap exists so a downtown does not wall off the camera, and a landmark is the one thing that should tower, so the cap is lifted for it and it keeps its real height. And the extruder now recognises three silhouettes from the same footprint: a tower in four rings that step in by half each time and end in a mast, a spire over a squat nave, and an obelisk. Anything else whose height is more than five times its width gets its top stepped in to 78%, because a slim footprint extruded straight reads as a slab. The geometry is shared — the tower's rings are the footprint scaled towards its centroid, connected by a leaning wall — so a landmark costs no asset and no draw call.

41. **The selection cage is four uprights, not one per vertex.** Selecting a building drew a vertical line on every point of its footprint, which is right for a four-sided block and wrong for anything curved: the Eiffel Tower's footprint has 116 points, so selecting it drew a forest of three-hundred-metre lines — the eighth playtest report ("porque fica esse monte de linha amarela quando seleciono a torre?"). The rings stay complete, because they are the shape; the uprights are now the corners where the outline actually turns, and a footprint with more than twelve points gets four, at its extremes — a cage that says "this one", which is all a selection has to say.

42. **A wall drag follows the mouse, and a blueprint is visible while it is a promise.** Two things made walls feel broken on an imported map (the ninth playtest report, at the Eiffel Tower). The line snapped to the dominant axis — drag at forty-five degrees and the wall ran ninety degrees away from the cursor, which on a wide open lawn looked like the game ignoring the drag. It is now a Bresenham line between the two cells, any angle, every step adjacent so there are no holes, and the test also pins that it is the same line drawn from either end. And a blueprint was drawn at eight percent of the final height, a hairline on the grass: a row of them read as nothing at all, so a player who had just placed twenty walls saw an empty field. A ghost is a promise, not a progress bar — it starts at thirty-five percent of the wall's height and shows its progress from there.

43. **A diagonal wall is a diagonal, and its pieces are stretched to meet.** The wall panel is two metres long and oriented by its four orthogonal neighbours, which is right for a straight run and wrong the moment the line is diagonal: a Bresenham line steps corner to corner, a diagonal neighbour is 2.83 m away, and every piece was left lying across the line — a diagonal wall came out as a row of dashes, the tenth playtest report. The frame now looks at all eight neighbours: with no orthogonal neighbour but a diagonal one, the panel turns to that diagonal and stretches by √2, which is exactly the distance between the two cell centres, so the pieces meet. Orthogonal neighbours still win, because a cell that touches east and north-east is a corner, not a diagonal.

44. **Survivors push each other apart, and the ones without a path push too.** Separation existed for the infected only — a horde spread along a wall, and the settlement's own people did not move at all, so four of them queued at a door and idled on the same tile. Measured across four days on five seeds: the worst pair stood on the same spot for 15,001 consecutive ticks, more than a game day, and 137,168 ticks in total had two people inside sixty centimetres. Two changes. The push covers survivors as well, with 1.35 m of personal space instead of the horde's 0.7 m — a person is 0.7 m wide, so a metre apart was still one silhouette from an RTS camera, and 1.35 m is still under one 2 m cell, so a queue at a door still fits. And it runs for entities with no mover and no path: a guard at its post is exactly the pair that stayed stacked, and the first version of the fix skipped anything the movement system had nothing to move. After: the longest merged run is four ticks, a blink, and the tick total falls by three orders of magnitude. Each survivor also gets a small deterministic shift in hue and lightness, because identical figures standing shoulder to shoulder merge into one silhouette however far apart they are.

45. **A building with a courtyard is imported, and the courtyard is open air.** OSM maps a block with an inner yard — a Parisian block, a hospital with a square inside — as a multipolygon relation: one outer way and one inner way per hole. The importer read ways only, so those buildings did not exist on the map at all, and a yard that arrived as a plain way was stamped solid and drawn as roof. Relations are now read, the outer ring becomes the footprint and each inner ring a hole: the roof is triangulated around the yard, the yard gets walls facing into it, and the navigation grid leaves its cells free so a survivor can walk through the arch into the courtyard. Area is what stands, not what the outline encloses. On a live Paris import at 600 m, three buildings carry a courtyard; at 700 m, six. The query costs about seven seconds more on a loaded Overpass and thirty kilobytes, which is why it is one added line rather than a second request.
46. **Post-processing is on by the driver, not by a setting.** Bloom and the grade are four full-screen passes: nothing on a GPU, and a visible cut on a software rasteriser that already spends 360 ms a frame, which is what CI and every probe run on. So `auto` reads the driver's name and stays off for SwiftShader and llvmpipe, the opt-in captures force it with `?post=on` because they show the game as a player sees it, and F4 overrides it either way and is remembered. The grade runs after tone mapping, on display colour, where contrast and saturation mean what they say; the bloom runs before it, on the half-float scene, where a lamp is still brighter than white. The mood is a pure function of daylight (`moodAt`), so it is unit-tested without WebGL. The night's threshold is low (0.32) because at night only lights are bright; by day it is 0.92, so pale concrete in the sun does not glow.
47. **Weather is drawn, not simulated.** The day's weather comes from the seed (`weatherFor`), so a run looks the same every time, and it lives entirely in the renderer: the simulation has no idea it is raining. That is deliberate for now. Every balance number in `BALANCE.md` was measured without weather, and a rain that shortened sight or muffled gunfire would move them all before a single human has played; the picture can ship today, the rule waits for the playtest to ask for it. Day one is always clear because it is the first thing a player sees.
48. **Occlusion at the wall's foot is geometry.** A screen-space pass needs a depth and a normal buffer, a GPU to be affordable, and care with every billboard in the scene. The place it matters most from an RTS camera is the pavement beside a wall, and that is known ahead of time: a skirt around each outline, dark at the wall and transparent a few metres out, taller buildings reaching farther. One draw call, identical under a software rasteriser, and unit-tested as plain numbers.
49. **Characters are skinned in the generator and shipped as morphs.** three.js instances a mesh with per-instance morph weights, and has no instanced skinning; a skeleton per survivor would be a draw call and a bone texture each. So the skeleton lives only in `tools/blender/characters.py`: the body is bound to bones there, every key pose is skinned there, and the game receives 26 morph targets it blends on the GPU for hundreds of instances in six draw calls. The cost is that a blend between two keys is a straight line per vertex, which shortens anything that rotates far between them. That is why a run has twelve keys and a walk eight, why a joint is spread over three rings, and why `characterAssets.test.ts` measures triangle area half way between every pair of adjacent keys. Feet do not slide because the stance of each gait is authored to cover the same metres the renderer advances the phase by, and the generator asserts the two agree.
50. **Water and railways are a second, optional request, and a street always wins.** A river is a multipolygon whose rings can run for kilometres and arrive as chains of unordered, unoriented ways, so its answer can be far larger than the city's. It is asked for on its own (`overpassTerrainQuery`) and cached under its own key: a slow or refused answer costs the water, not the map, and an area saved before this existed fetches it the next time. The outline is joined end to end from shared points (`joinRings`); a chain that never closes is dropped, not guessed at. On the grid, water is `CellKind.Water` (nobody crosses it, nothing is built on it) and a railway is `CellKind.Rail` (walkable, because people do cross tracks, but not a place to build); a street across water is a bridge and across a railway a level crossing, so road corridors are masked out of both, a building is never drowned, and a railway bridge keeps its deck. Water is filled by one scanline per row with the outline and its islands counted together (even-odd), which is what makes a 3,000-point river cheap. Measured on two real 480 m areas of Paris: 13,792 and 15,778 water cells, 996 rail cells, the import under 300 ms, and three buildings lost to the Seine at one of them, all standing in it with no dry door. Tunnels, culverts, trams and subways are ignored; the sea (`natural=coastline`) is not read yet.
51. **A lattice tower is open iron on four piers.** Decision 40 drew the Eiffel Tower as four solid rings stepping in, wearing a shop facade: from the default camera a striped skirt the size of a city block, whose 9,738 m² footprint was solid on the grid, and at 330 m taller than the camera ever climbs (about 255 m at the farthest zoom), so it filled the screen with a wall. OSM tags it `tower:construction=lattice`, and that tag now makes it a `lattice` landmark (pillar 1: the place has to read as itself, and the map around it has to stay playable). It is drawn as members, not surfaces (`lattice.ts`): four legs that lean in from piers at the corners of the base and join at the second platform, braced on every face, an arch on each side under the first platform, the platforms, a single shaft and a mast, all in one untextured iron group painted the tower's own brown. Its frame is the smallest rectangle around the footprint, which for an outline of four legs joined by arches is the square through their tips. On the grid only the four piers are building (`latticeLegs`, about a quarter of the old footprint), and the esplanade between them is open ground to walk, fight and build on. It keeps its real height: seen through, a tower that leaves the top of the screen hides almost nothing. The cost is 23,000 vertices for the tower, one more material in the building batch, and no new draw call when no lattice tower is on the map. A save made before this keeps the map it embedded, so the tower in it stays solid.
52. **Water is a river with banks, and a bridge is a deck.** The Seine at the Eiffel Tower was a flat teal sheet, and the Pont d'Iéna two narrow lanes with water between them: OSM maps the bridge's roads as service lanes and footways, and the importer drew only the lanes. Three changes (pillar 1: the place has to read as itself). The surface is a shader on the same flat mesh (`water.ts`): a distance-to-bank texture computed once from the reclamation field shades it murky green at the walls and dark in the middle, with a pale lap along the quay, and a sum of six travelling sines with no common period turns into a normal, so the sun glints and the sky shows where the environment is on, without a reflection pass. The distance is measured to where the water ends, not to a deck laid over it, and past the map's edge the river is extended rather than given a bank. The banks get a stone coping on their land side, except where a street or a bridge meets the water and along the map's border, where the river was cut rather than ending. And the terrain request now asks for `man_made=bridge`: the deck outline is dry ground on the grid, paved like the sidewalks it continues, with a parapet wherever its edge stands over water. The water stays at street level: lowering it would mean cutting the ground plane along the river, and the field's two-metre cells would leave a ragged edge that the coping could not hide. The water cache key moved to `terrain2:`, so a place saved before this fetches its water and bridges once more; a save keeps the map it embedded, without decks. The 400 m Eiffel map shows a strip of the Seine and the 600 m one much more of it because the river runs 179 m from the tower: that is geography, not a loss in the import.
53. **Pyramids and amphitheatres are drawn as themselves.** Tried on the seven wonders and Giza (2026-11-20), the three that load drew their wonder as a block: the Colosseum a two-storey disc, the pyramid at Chichén Itzá an office building with windows, the Great Pyramid a twenty-storey block of flats. Three more silhouettes join decision 40, read from tags (pillar 1): `pyramid` for `tomb=pyramid` or a pyramidal roof as tall as the building (a house's pyramidal roof is a few metres over its walls, and towers are excluded), drawn as four faces to an apex; `stepped` for `building=pyramid`, which OSM uses mostly for Mesoamerican pyramids, drawn as terraces to a platform at four fifths of the height with a stair up each face and a temple on top; and `amphitheatre` for `building=amphitheatre`, an outer wall in four storeys with cornice bands and, inside, no roof but tiers of seating stepping down to an arena floor. All three are dressed stone, one colour whatever the building is classified as. A landmark's `height` now wins over its `building:levels` (the Great Pyramid is tagged forty levels, which the twenty-floor cap turned into 65 m instead of 139), and an amphitheatre without a height rises about a quarter of its width, which gives the Colosseum 39 m against a real 48. On the grid the three stay solid, arena included: the bowl is for the eye, and the building is searched like any other. The same test found that a building relation's outline arriving in several ways was read one way at a time (the Colosseum lost half its footprint and the Chichén pyramid vanished), fixed by joining the pieces first. Still not drawn: domes (the Taj Mahal does not load yet), statues (Christ the Redeemer is a node the request does not ask for) and city walls (the Great Wall is `barrier=city_wall`, not a building).
54. **A pond in a park shows.** The lawns of parks are drawn four centimetres above the ground and the water two below it, so the ponds of the Jardin de la Tour Eiffel were lawn with a quay round them (a playtest report with the map beside it). Raising the water was not an option: roads and bridge decks are laid at three centimetres and must stay over it. Cutting the ponds out of the park meshes would handle a pond inside a park but not one half in it, which the same area also has. So the reclamation texture carries dry land in its alpha (zero where water runs, bridges included) and the park shader discards where it is wet. The field's cells are about a metre and a third, filtered, so the cut follows the outline to well under a metre, and the quay's coping covers the land side of it. The coping itself is now the outline grown by its width and mitred at each corner, instead of a strip per edge, which left a notch at every turn of a pond's shore.
55. **Gunfire noise is a thin line, not a wave.** The noise ring shows how far a shot carries (45 m for a pistol, 70 m for a rifle), which is pillar 3's telegraph: the player sees what a shot will pull in. Decision 21's flipbook drew it as a white wave stretched over the whole radius; at 90 and 140 m the sheet's stroke became a blurred band several metres wide, drawn additively, and from a low camera its near side swept across the screen like a shockwave every second of a fight (a playtest report: "essa onda quando os civis atiram"). It is now a line drawn in a shader on a flat quad (`noiseRing.ts`): about two pixels wide at any distance (the width follows `fwidth` of the distance from the shot, so the near side does not swell), a warning amber blended over the ground with a thin shade just inside it, opening fast over the first 45% of 1.6 s, then holding at full reach while it fades, so the reach can be read rather than glimpsed. A spot gets one ring every 2.5 s however fast the shots come, and at most three are alive. The flipbook sheet is no longer loaded.
56. **A heritage site is a place to play.** Tried on the seven wonders (decision 53), five did not load. Machu Picchu and the Great Wall at Badaling have no street in 480 m, only paths and steps; the Taj Mahal has nine buildings around it and Christ the Redeemer ten, under the twelve the importer demanded. Neither rule had a recorded reason, and nothing in the simulation depends on either: the hordes need ways in from the border and the economy needs buildings, not streets for cars or a dozen buildings. So an area whose streets come to less than 1.5 km (the Eiffel Tower and the Colosseum have over 5 km, the Taj Mahal 0.2, Christ the Redeemer 0.8, Giza 1.1) walks its footpaths, paths, steps, bridleways and cycleways as streets too, at their own narrow width; they are drawn as packed earth, with no sidewalk, kerb or street wear, and no abandoned car (vehicles need a way 7 m wide). And a map needs five buildings, not twelve: a headquarters and a few to search. A poor site is a hard game (pillar 3), and the player sees how many buildings there are before founding a base. Played by the autoplayer for four days each, Machu Picchu, the Taj Mahal, Christ the Redeemer and Chichén Itzá ran with no navigation failure, eight hordes each arriving along the paths, and the Taj Mahal's scavenging the scarcest (three buildings searched). The Great Wall still does not load: two buildings, and the wall itself is a barrier, not a building. Petra was not tested: Overpass timed out on it from the game and from the command line.
57. **Imported maps have relief, drawn at half its height (phase 1: the look, no rules).** Christ the Redeemer stands on a hill that rises 400 m inside its 480 m map, and Machu Picchu sits on a ridge 260 m above its own valley; drawn flat, both were a car park with ruins on it. The relief comes from the open AWS Terrain Tiles (Terrarium encoding, zoom 15, about 4.5 m a pixel, public and served with CORS): a third request when a place loads, optional like the water, kept in the browser cache, and `?terrain=0` turns it off. It becomes a grid of heights every 4 m over the map (`TerrainDef`, decimetres above the lowest point, 14,641 values for 480 m, kept in the map and so in saves), and `heightAt` reads it bilinearly; an area with less than 2 m of relief stays flat. It is drawn at half its real height (`TERRAIN_SCALE`): at three quarters and at full height Corcovado became a wall that filled half the screen and hid its own summit from a camera that climbs to 255 m at most. In the renderer, the base ground becomes a grid that follows the relief and holds the edge's height beyond the map; every flat layer (lawns, roads, trails, sidewalks, water, quays, bridges, rails, markings, contact shadows, wear decals) is laid over it in one pass that splits triangles to 4 m and raises each vertex; buildings stand on the lowest ground under their outline, the uphill wall running into the hill, and the facade shader measures grime from that base; units, structures, props, roof props, trees, grass, doors, markers, effects, tracers and the noise ring take the ground under them; picking marches the camera ray down to the surface; and the camera looks at the ground under its target. On Corcovado this adds 85 ms to building the ground and takes it from 10,000 to 150,000 vertices, against a frame that is fill-bound. The simulation does not read the relief yet: slopes cost nothing to climb and give no advantage (phase 2). The e2e real-place test serves a synthetic rolling tile, so the whole relief path, a click on a building on a slope included, runs offline.
58. **Relief is a rule: cliffs, climbs and high ground (phase 2).** Decision 57 drew the relief and let nothing read it. Four rules now do, all on the drawn heights the player sees (pillar 2: high ground is a position to hold; pillar 3: the route over the hill or round it is a choice). Measured on the drawn relief, Corcovado's slopes run from a median grade of 0.29 to 2.3 on its flanks, Machu Picchu's from 0.31 to 0.95, the Eiffel Tower's never past 0.13. **Cliffs:** a cell steeper than grade 1 (45 degrees) toward any neighbour is `CellKind.Cliff`, which nobody crosses and nothing is built on, except where a street or a path runs (they win, as over water); on Corcovado that is 13% of the map, on Machu Picchu nothing. The relief now reaches the importer before doors are chosen, so a building whose door the cliffs cut off is dropped like one in a closed courtyard. **Climbs:** walking uphill is slower, speed over (1 + 1.5 x rise), and never faster downhill; a survivor's path prices the climb the same way, so it takes a detour round a steep hill when that is quicker, and string pulling no longer straightens a path back over the hill it went round. The horde field does not price slope: priced, it took a second to build over Machu Picchu, a stall in the middle of a night, and a horde walking straight up a hill, slowed by it, is what a horde does. **High ground:** a shooter reaches 2% further per metre above the target, up to 30%. **Building:** nothing stands on ground steeper than 0.5. The elevation source has voids (near the Taj Mahal a few pixels read -233 m in ground between 147 and 185), so a node more than 25 m from its neighbours' median takes the median. Autoplayed four days: Corcovado and Machu Picchu ran with no navigation failure, the worst tick no slower than on the flat map (84 ms against 86 on Machu Picchu) and the average 27 µs against 22, and fewer survivors lost (one against two on Corcovado, two against five on Machu Picchu), the hordes slowed on the climb to the base. A map saved between decisions 57 and 58 has its relief but was imported without it: its cliffs may now cut off a door the import kept.
59. **A hillside is finished: plinths, level water, and a reason for a red slope (phase 3).** Three things decisions 57 and 58 left rough. A building stood on the lowest ground under its outline, so on a steep slope the hill could reach past its roof: it is now raised until its roof clears the highest ground by up to 2.5 m (half its height for a low one), on a stone plinth down to the lowest, and its door stands on the plinth when the ground in front is lower (`buildingSeat`, shared by the batch, the doors and every marker). A wall, gate, tower, farm or well built on a slope stood at the ground under its centre, one end buried and the other in the air: it now stands on the highest of its corners, with a stone plinth to the lowest. Water followed the ground like everything else; each lake or reach of river now lies level at the lowest ground on its shore, the ground under it is cut 1.5 m below that level (sloping to the bank over one grid cell), and the quays' coping follows the bank while their face drops to the water — on the Seine, the sunken quay decision 52 could not draw on a flat map. Water is no longer draped, nor are the quays. And a piece the slope forbids is red with a reason: the build banner says the ground is too steep. A flat map is untouched: every seat, level and plinth is 0.
60. **Domes and city walls (the Taj Mahal, the Great Wall).** The two wonders decision 53 left undrawn. The Taj Mahal is tagged `tomb=mausoleum` and nothing about its roof, its outline is its 95 m platform, and its minarets are not mapped as buildings; a mosque was drawn with a church's spire. A `dome` landmark is now `roof:shape=dome|onion`, `tomb=mausoleum` or `building=mosque`: a platform the size of the footprint, a hall on it with a cornice, a drum and an onion dome swelling past it to a finial, all turned round its axis, about six tenths of the footprint's width tall when OSM gives no height (65 m for the Taj Mahal's 73). Minarets OSM maps on the platform are kept with it instead of dropped as contained buildings; a mausoleum on a near-square platform 60 m or more across gets four at its corners when none are mapped, which is the Taj Mahal's plan and no smaller tomb's. A landmark wears its own colour from `building:colour` or `roof:colour` (the Taj Mahal's white, the Colosseum's sand), named or hex; an ordinary building keeps the palette. A defensive watchtower (`tower:type=defensive`) is a block, not a tapering tower. City walls (`barrier=city_wall`, `historic=citywalls`) come with the water and bridges in the second request (cache key `terrain3:`): read as walls with their own height and width, never as paths even when, like the Great Wall, they are also tagged as steps; drawn as a band of masonry with a walk and merlons on both edges, every metre on the ground under it, so the Great Wall rides its ridge; and on the grid they are `CellKind.Rampart`, which nobody crosses, except where a street goes through (a gate) and beside a building on the wall (a watchtower is how the Great Wall is crossed). Behind a wall a map needs two buildings, not five: Badaling has two watchtowers in 480 m, and the wall is what that map is about. Ávila's walls, nine OSM ways with their round towers, load and draw the same way. Christ the Redeemer's statue is still not drawn: it is a node the request does not ask for.
61. **Statues stand on their pedestals (Christ the Redeemer).** OSM maps Christ the Redeemer as one point: `man_made=monument`, `subject:wikidata=Q302` (Jesus), no height and nothing that says statue. Points tagged `man_made=statue|monument` or `memorial=statue` now come with the water, bridges and walls in the second request (`MonumentDef`, `CityMap.monuments`; cache key `terrain4:`) and are drawn on the ground under them: a stepped pedestal and a robed figure with its head, in weathered bronze; a statue of Christ opens its arms with its sleeves hanging, in pale soapstone, at Christ the Redeemer's proportions (30 m on an 8 m pedestal) unless OSM gives a height; a monument that is not a statue is a column with a capital. A tagged height is the whole, the pedestal keeping its share. The pedestal is `CellKind.Rampart` on the grid. These are not buildings: nothing to search or to found a base in. A city's many small statues get a figure each, 3.5 m on a 2 m pedestal, which is their real scale and reads as street furniture from the camera.
62. **A watchtower is masonry with battlements.** Decision 60 kept the Great Wall's towers (`tower:type=defensive`) from tapering like a radio mast, and they became ordinary buildings: small houses with windows and a water tank on the roof, standing on the wall. A `watchtower` landmark (`tower:type=defensive`, `defensive_tower=yes`, `castle_type=defensive`) is now a block of plain stone with no facade, a flat roof behind a parapet, and merlons along every edge of it, in the same worn stone as the other ancient landmarks; untagged, it stands a little taller than it is wide. No landmark carries the roof kit any more (a pyramid's temple and the Taj Mahal's platform had air conditioners on them).
63. **A building on a slope grows downhill; it is never raised.** Decision 59 raised a building whose hill would reach past its roof onto a stone plinth. On a low building across a steep street that meant a warehouse 4.6 m tall standing on a plinth nearly 6 m high, its door hanging off the top of it: at Copacabana 26 of 221 doors stood above the ground in front of them, the worst by 6 m (a playtest report at night, the base's door lit in mid-air). A building now always stands on the lowest ground under its outline, and when the hill would reach its roof it gains whole storeys instead, so its roof clears the highest ground by up to 2.5 m: the downhill side is taller, as a building cut into a slope is, and the facade's windows run on down it. Its door stands on the ground where it meets the wall, not a metre out; measured again at Copacabana, every one of the 221 is at the wall's foot. The flag, the base marker, the selection outline and the roof kit follow the drawn height (`buildingSeat` returns it). Landmarks keep their own height. Ground floor windows on the uphill side still run into the hill, as a basement's do.
64. **A tomb carved into a cliff is drawn as its facade in the rock.** Petra's Treasury is mapped as `building=yes`, `historic=tomb`, `tomb=rock-cut` on an outline 12 by 18 m, and it was drawn as a one-storey shed 3.8 m tall: the nearest building to the map's centre, so the one a player was likeliest to make a base. A building tagged `tomb=rock-cut` (or `historic=rock_cut`, or of `building:material=rock`) is now a `rockcut` landmark, untagged about twice as tall as its outline is long (39 m at the Treasury, as built). It is drawn as a wall of rose sandstone with the temple front cut into it on the side its door faces: six columns, an entablature and a pediment below, a round kiosk between two half-pavilions above, an urn on the kiosk. The cliff is wider and deeper than the outline, by about half the facade's width at each side and a third behind, because on the outline alone the Treasury stood on the plain like a brick tower; the rock round it is scenery, and the ground rules still read the outline (pillar 1: a real place should read as itself at a glance). Petra loads at 600 m, not 480, where three buildings is under the minimum; the ground is still grass, where Petra is bare sandstone.
65. **A desert has a desert's ground.** Every imported map took its overgrowth from a temperate city: moss, rank grass and saplings over everything. At Petra that laid green patches and grass over bare sandstone. A map now knows whether it is in a desert (`climate: "arid"`, kept with it and so with saves) from a short table of the world's deserts by latitude and longitude, Köppen's BW: the Sahara and the Nile, Sinai and southern Jordan, Arabia and Mesopotamia, the Gulf, Thar, the Taklamakan, the Gobi, the Mojave and Sonora, the Atacama, Australia's interior, the Namib and the Kalahari. The table is coarse on purpose: OSM rarely maps bare ground (Petra's 600 m have none), and a fourth request for it would go to a server that is often busy. Its edges were checked on both sides (Petra, Giza, Dubai, Las Vegas and Antofagasta are desert; Jerusalem, Los Angeles, Copacabana, Paris and Machu Picchu are not). In a desert the base is sandstone and dust, the reclamation field keeps four tenths of its growth (the drift it leaves is pale blown sand and its growth dry scrub, in the ground shader), the grass that remains is straw, and three in four trees that seeded themselves outside a garden are dead snags (pillar 1: the place has to read as itself). A map imported before this has no climate and keeps the green.
66. **A survivor walks about its chores and runs when there is a reason to.** Every survivor moved at 3.0 m/s and the animation drew every step as a jog: the settlement trotted to the well and back all day, and the walk the character tool authors for survivors was never shown (a playtest report: the movement looks bad). A survivor now goes at a brisk walk, 1.7 m/s, unless it is in a hurry: sent by the player (a manual unit or a move order), attacking, fleeing, falling back to base or defending, or with an infected within 24 m. Then it jogs at 3.0 as before. Load and wounds still slow either pace. The animation follows the speed the survivor is actually going at, with two thresholds (jog above 2.15 m/s, walk below 1.95) so a pace between them does not flicker, and the two gaits share one phase, so a change cross-fades the cycles in step over about half a second instead of switching. Seen from the camera, a running survivor now means something is wrong (pillar 4: the community is the resource, and its state should read at a glance; pillar 3: the moment a trip turns dangerous shows). Swept over 12 seeds for six days with the fortifying bot, economy and crafting on: defeats went from 4 to 1, structures built from 539 to 525 (-3%), survivors alive at the end from 96 to 88; within the spread twelve seeds give. Saves are unaffected: the pace is decided each tick.

67. **No two infected walk alike.** Every infected shared one walk, one height and one pace, so a horde came down the street in step, a parade rather than a crowd (a playtest report: the zombies' movement looks bad). Each body now differs from the next, fixed by its id so it never changes between frames or loads. Half are drawn mirrored, so the other leg drags and the other arm hangs: a twin batch with a negative scale on the object, which makes Three turn the winding round so faces and shadows stay the right way out. Height varies by ±8%, and the stride scales with it, so a taller body takes fewer, longer steps at the same pace. Each carries itself its own way, pivoting on its feet: a forward lean of -2° to 6°, a list of up to 4° to either side, and a rock of 1.5° to 4.5° from foot to foot in time with the stride. And the pace itself is spread: each infected moves at its kind's speed ±12%, from a hash of its id, so the mean of a horde is unchanged but it strings out as it comes, the quick ones first (pillar 2: night is a promise, and the horde should read as a mass of the dead, not a formation). Swept over 12 seeds for six days with the fortifying bot, economy and crafting on, against the run for decision 66: defeats went from 1 to 3, structures built from 525 to 543, survivors alive at the end from 88 to 81, infected killed from 1,739 to 1,699. The defeats are within the spread twelve seeds give (decision 66 went from 4 to 1), but they are the number to watch. A saved infected keeps the speed it was saved with; one saved before this walks at its kind's speed.

68. **People lean into a turn, wait like people, and step aside rather than moonwalk.** Three things still made the survivors look like counters on a board (a playtest report: the movement looks bad). A body went round a corner bolt upright; it now leans into the turn by 0.6 × atan(speed × turn rate / g), at most 12°, pivoting on its feet, and stands up again on the straight. The infected lean the same way, on top of their own posture (decision 67). A survivor waiting for work stood frozen on its spot all day; now and then (every 16 s on average) it takes a few steps, 1.2 to 3.5 m to somewhere open, and more often (every 11 s) it turns to look somewhere else. When that happens is decided by a hash of the tick and the id, so waiting draws on the random stream only when someone does move, and the old pull back to within 24 m of the base still holds. And the crowd push (decision 44) moves a body sideways when two stand too close, which the animation played as the walk: someone shoved to the side walked on the spot facing the wrong way. The share of the motion that goes the way the body faces now drives the stride, and the rest is played as the weight shifting onto the other leg. Pillar 4: the community is the resource, and it should read as people. Swept over 12 seeds for six days with the fortifying bot, economy and crafting on, against main after decision 67: defeats went from 3 to 1, structures built from 543 to 553, survivors alive at the end from 81 to 106, infected killed from 1,699 to 1,786. Loitering cannot plausibly help that much; this is the spread of twelve seeds, in the other direction from decision 67.

69. **Characters are skinned on the GPU from a bone texture; morphs are gone.** Decision 49 baked every key pose to a morph target and blended them per instance, which moves each vertex along a straight line between two keys: anything that turns between them gets shorter half way, a shin in a run worst of all (a playtest report: the movement looks bad). More keys would only have made the error smaller, and at 26 morphs the models were already 486 KB and 401 KB against a 512 KB ceiling. So the skeleton now ships with the model. The generator exports the body in its rest stance, each vertex's two bones and weight (as one morph target named `bind`, so they follow the exporter's vertex order), and in the object's extras the seventeen bones, their parents and every key pose as a rotation per bone plus the root's position: 16 walk keys, 24 run keys and the six others. In the renderer a person's pose is a weighted sum of those rotations, normalised, with the bones hung off one another by forward kinematics, so every bone keeps its length whatever the blend. Each batch writes its people's 3×4 bone matrices into the rows of one float texture, and the colour and shadow-depth shaders skin each vertex by its two bones from its instance's row. It is the same instanced draw calls as before, one per material and mirrored twin, with no skeleton or draw call per person. The generator checks that every bone hangs off its parent to 0.1 mm and that the exported rig reproduces its own skinning. `characterAssets.test.ts` now finds the body's total surface area half way between every pair of adjacent keys within 1% of the keys' own, against a worst triangle of 0.12 before. The models dropped to 96 KB and 85 KB. Measured on the RTX 4050 machine with 600 infected on screen: posing them costs 2.3 ms of CPU a frame against 1.1 ms for the morph weights, and the GPU frame is unchanged (0.7 ms against 0.8 ms). Pillar 2: night is a promise, and the horde should look like bodies, not like vertices sliding between poses.

70. **Christ the Redeemer and the Taj Mahal are drawn after the real ones.** Both read as placeholders next to the Eiffel Tower (a playtest report: the Christ can improve a lot, and the Taj Mahal too). Christ's figure was a round column with a beam across it and two blocks under the beam, and its head looked like a helmet. The figure is now built from rings. Its proportions are measured off a photograph, and it is drawn as smooth surfaces (about 84,000 triangles, on the one map that has it) rather than as faceted rings. The tunic falls almost straight, 6.7 m across at the feet and 9.6 m at the shoulders, in deep pleats under a cord knotted at the waist, its tasselled ends hanging down the front, with the feet showing under the hem and the Sacred Heart in relief on the chest. The mantle over it hangs in curved folds from shoulder to shoulder across the chest, and its edge runs down the figure's left side to the knee; behind, it hangs almost to the hem in long folds. Each arm is one piece with its wide sleeve, which hangs lowest at the wrist and meets the body at the waist, in folds slanting down from the wrist. The hands are open, a tenth of the figure long (a playtest report: they looked small), and the arms are drawn a little shorter than their profile so the hands still end 28 m apart. The head is bowed from the neck, a long face carved in thirds (nose, eye sockets under the brow, cheekbones, moustache, short beard), under a separate shell of hair parted in the middle, swept back from the forehead and falling past the cheeks and down behind to the shoulders in wavy locks. Every crease is darkened in the vertex colour by how far it sits below its neighbours: the game's sky light is strong and even, and without that the folds vanished into one pale shape. It stands on a dark pedestal under a pale band, with three steps round it and the chapel door at the back. It faces +z, so the default camera sees the cross at 45° rather than edge on; the real statue faces the bay. The domed hall was a box under a dome 36 m wide. It is now a hall with its corners cut, six tenths of the platform across. Each face has a pointed-arch iwan 3 m deep with a doorway in the darker tone, set in a frame that rises over the roof line between alcoves stacked two high. Pinnacles stand at its corners, and there is a kiosk at each corner of the roof. The onion is about two fifths of the hall across, over a drum, closing to a lotus and a finial. The minarets are slim and rise in three stages, each ending in a balcony, under a kiosk. A mosque gets the same hall; one smaller than 40 m across keeps plain faces between its iwans. Pillar 1: reclaim the city, and a wonder is why the player chose it.

71. **A straight wall and a slanted wall meet at the corner, and a gate goes where it can be walked through.** An audit of the build system over 37 layouts (runs along the axes, at 45° and at any angle, L, T and cross junctions, closed rings as squares, diamonds, octagons and irregular pentagons and hexagons, and gates in every orientation) found two defects (a playtest request: check walls and gates in many directions and more complex shapes). Every ring sealed the infected out, but where a run along a grid axis met a slanted one the corner was open or overran: the first straight panel stopped at its cell's edge, about 1.4 m from the diagonal, and the old run's end panel ran on half a cell past the corner, so an octagon showed a notch or a stub at each of its eight corners. The corner join now treats a straight run as a run at its own axis: the panels on both sides end at the corner cell's centre. Two straight runs still meet in the junction pier, which fills the cell. And a gate could be set into the corner of a wall, or where three runs meet, where the cells beyond it on every side are wall: survivors may not cut a corner, so nobody could walk through it, and the gate's straight panel left the other run open beside it. A gate now needs open ground (or another gate) on two opposite sides, counting wall blueprints that will close them, and it does not go into a panel cut back to the corner of two slanted runs, where it was drawn squeezed to half its width. The build preview shows those cells red, as it asks the same question. The same audit asked whether the infected really cross walls or only look as if they do (a playtest question). They crossed: a diagonal wall is a staircase of cells that touch only at their corners, and a body's step was checked only where it ended, so a crowd walking at the middle of a closed diamond went straight through it, 72 of 80 in 30 seconds; a ring along the axes held them all. Pathfinding never cut those corners, but the step itself, and the crowd push, did. A step into a diagonal cell now needs both cells beside it walkable, as a path does, and the same crowd stays out of a diamond and a slanted hexagon. Pillar 2: night is a promise, and the wall the player draws against it has to close where it is drawn.

72. **A generated city has relief and a street plan of its own.** Every seed laid the generated city out the same way: six by five square blocks of 56 m on flat ground, so only the zones changed from one game to the next (a playtest report: it is always the same shape, flat, with no topology). A new game on a generated city is now drawn by `generateVariedCity` (`generated.ts`). It picks a site first: one or two round hills, an escarpment, rolling ground, or a river valley. The hills' steepest flank stays under a grade of 0.3, so it is built on and climbed slowly. The escarpment is a plateau broken off along a line, 13 to 17 m high, a face steeper than grade 1 that only the streets climb. Then it lays a street plan on it: five to seven by four to six blocks of uneven sizes (40 to 72 m), one avenue each way, and in a grid a few cross streets left out to join blocks into superblocks. In a valley a river 18 to 26 m wide wanders north to south on a flat floor, the slopes rising away from it on both sides, and only one to three streets cross it, on bridges; the others stop at its banks. The map comes out in the shape an imported place has (streets as centre lines, relief as a heightfield, water, bridge decks), so the rules of decision 58 apply as they are: climbing is slow, high ground shoots further, a cliff is crossed only by a street, and nobody walks on water but over a bridge (pillar 2: high ground is a position to hold; pillar 3: the bridge or the street up the escarpment is a choice of where to stand). Nothing is built in the water, on its banks or on the escarpment's face. Every door must be reachable from where the hordes come in, and a map has at least 40 buildings, with a hospital, a police station, a school and a supermarket; a plan that fails is drawn again from the same seed, so a seed always gives the same map. The banks stand 1.5 m above the river: the water is drawn at the lowest point of its course, and a valley floor level with it showed water through every flat block. The player picks its size in the menu: small, medium, large or huge, about 350, 450, 600 or 800 m across (the biggest real place loads at 600 m; a huge city is about 3.5 times the classic grid's area, some 450 to 520 buildings). The blocks are drawn at random and then scaled together, so a map is never larger than the size asked for and a little wider than it is tall; hills, valleys and the river's bends grow with it, and there is an avenue, a superblock and a bridge more for every few blocks. Medium is the default. A seed alone rebuilds the classic grid, so a save keeps a varied city whole (`generated:<seed>`), as it keeps an imported one; saves of classic cities load as before. The classic grid is still offered in the menu (Street plan: varied or classic, remembered per browser), and the browser tests start on it because they place things by its blocks. Swept over 12 seeds for six days with the fortifying bot, economy and crafting on, against the classic grid on the same seeds: 2 defeats in both, structures built 567 against 548, survivors alive at the end 94 against 73, infected killed 1,695 against 1,644, no navigation failure in either, the average tick 0.04 ms against 0.03. By size, over 8 seeds each, six days, the same bot: small 4 defeats, medium 0, large 1, huge 0; survivors alive at the end 53, 73, 79 and 57; infected killed 1,039, 1,127, 986 and 807; no navigation failure in any. A small city is the hard one: fewer buildings to scavenge, and the hordes reach the base sooner. A huge one is quieter at first, the hordes having further to walk. The average tick stays under 0.1 ms at every size; the worst rolling average over a run rose from 1.5 ms (medium) to 4.9 (large) and 7.3 (huge), the horde field being rebuilt over a grid up to four times larger. That is within a frame, but it is the number to watch.
