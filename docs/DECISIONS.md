# Architectural decisions

1. **Three.js over Babylon.js.** We need direct scene control, instancing and procedural geometry, not a full engine. Only one 3D library is used.
2. **Component-bag ECS instead of an ECS library.** Entities are plain objects with optional components. They are trivially serializable and fast enough for hundreds of agents. Archetype storage can be revisited if profiling demands it.
3. **Grid navigation (2 m cells) instead of a road graph for the MVP.** The procedural city is small (420 × 352 m, about 37k cells), so A* is cheap, and the same grid handles walls, gates and local movement. A road graph layer for long trips is planned with real maps.
4. **Shared distance field for hordes** instead of per-agent A*. Walls have a cost proportional to their HP, so hordes pick a breach point emergently, with no cheating spawns inside the base. The field is recomputed only when the grid version changes. Full recomputation is about 2 ms today. Region-local invalidation is a planned optimization for large maps.
5. **Global stock with physical storage nodes.** Each storage building holds its own stock, and workers physically carry materials from storage to sites. The HUD shows totals. Tower guards are resupplied abstractly.
6. **Renderer reads simulation state directly** (read-only) instead of copying snapshots. This is simpler and allocation-free. The command queue still enforces one-way mutation.
7. **No Web Worker yet.** The simulation costs well under 1 ms per frame — measured at 0.045 ms with a city, a squad and the task systems on a 25 entity map, and the render is the whole frame at 320 ms in a software renderer (see [PERF.md](PERF.md)). The core is DOM-free, so moving it to a worker later is mechanical, but it would free four hundredths of a millisecond and buy nothing.
8. **Time freezes while an event card is open or before a base is chosen**, so the player is never punished for reading.
9. **Units are drawn about 1.9× life size** so they read at strategic zoom levels.
10. **Real maps are imported in the browser, not by an offline tool.** The game is a static site on GitHub Pages, so the player's browser asks Overpass for one small area (400 to 600 m square) when they start, and keeps the answer in IndexedDB. One request per new game is light use of the public servers; nothing is fetched in bulk. Search uses Nominatim only on an explicit search.
11. **One building path for both map kinds.** Procedural rectangles and real footprints go through the same extruded-outline renderer. The grid stamps footprints by cell center; door, perimeter and window-fire code use the outline when there is one and the rectangle otherwise, so procedural balance is unchanged.
12. **Every real map gets a supermarket and a police station.** If the area has none, a mid-sized shop, office or warehouse near the center is promoted, because food and ammo depend on them.
13. **Pages from the `gh-pages` branch, with PR previews.** GitHub Pages serves a single site, so `main` is published to the branch root and each pull request to `pr-preview/pr-<number>/` in the same branch (`rossjrw/pr-preview-action`). The main deploy keeps that folder, and a closed PR removes its own. A fork cannot push to `gh-pages`, so it only uploads the built site; `pages-preview-fork.yml` on `main` publishes that artifact after the pull request head matches the run, and never checks out the fork.
14. **Commands are drained while time is frozen.** A pending event, a manual pause or a defeat stops the clock, but the command queue is still applied. Resolving an event is a command, so waiting for the next tick would deadlock the modal; applying commands without advancing the clock keeps the UI responsive and preserves determinism. Commands are discarded after defeat.
15. **The debug controller is development-only.** `window.__afterfall` is assigned only under Vite's `import.meta.env.DEV`, so the production bundle does not expose a mutable simulation handle. The Playwright suite runs against the dev server and keeps using the hook; CI rejects the string in `apps/web/dist`.
16. **Saves are validated before load.** `deserialize` rejects newer versions, malformed internals, OSM saves without their embedded map and states whose building count does not match the map. Imported maps must keep the same building order they had when saved, and migrations are added per version bump.
17. **Quality gates run in CI.** ESLint and Prettier check the code, Vitest enforces V8 coverage thresholds, `pnpm audit` blocks high or critical advisories, and a WebKit smoke test checks the shell beyond Chromium. Firefox smoke is available locally; the hosted runner lacks a Firefox WebGL context without extra OS packages.
18. **The Linux desktop build is a snap of the web game.** `apps/desktop` is an Electron shell that serves `apps/web/dist` from `app://game/` and adds only a quit bridge. The Snap Store builds `snap/snapcraft.yaml` on `main` and releases it to edge. CI builds the same file, installs it and runs `--smoke`, which starts a generated city and checks the HUD, local storage and the quit bridge. The smoke does not use `window.__afterfall`. Real-map downloads are allowed to reach Overpass and Nominatim; the rest of the game stays offline.
19. **Sound is a separate package driven by the simulation, never by the UI.** `@afterfall/audio` keeps the sound table and the event mapping pure (no DOM, no Three), and its director reads `sim.fx` and `sim.state.alerts`, so combat, construction and night alarms make noise without any component wiring sound by hand. The browser only unlocks an `AudioContext` on the first gesture and feeds the director once per frame. Voices are capped per sound and globally, and a backlog larger than a couple of dozen events is dropped instead of dumped, so a paused tab never returns in a burst of noise. Positional sound is approximated from the screen centre in world space (pan ignores camera rotation for now). Volume and mute live in the UI store and are persisted with the language (`afterfall.volume`, `afterfall.muted`); the director follows the store instead of the UI calling it. Day and night each get a looping ambience bed, crossfaded over 1.2 s when the clock changes half of the day.
20. **Impact effects are particles instanced from the same events as the sound.** `VfxSystem` reads `sim.fx` and turns each hit, death, melee, shot and build into a short-lived burst of billboarded quads in one `InstancedMesh` (one draw call; the particle is a radial gradient drawn to a canvas). Additive blending doubles as the fade — the instance colour runs to black as the particle ages, so no per-particle material or alpha sorting is needed. Physics uses a clamped step, but lifetime consumes the real delta, so returning from a background tab never leaves ghosts on screen.
21. **Each event has its own flipbook, and dull ones blend normally.** On top of the particles, a pool of 24 billboarded quads plays a flipbook per event: a muzzle flash for shots, a cloud for deaths, dust for work ticks, a claw slash for infected strikes, and the original spark for hits. Flash and spark are additive; the clouds are not, because adding a dark or dull colour adds nothing, so they use normal blending, fade by opacity and replace the particles of their event (twenty additive red particles glowed like neon over the death cloud). The strike is additive like the flash, but drops its particles as well: eight pale blobs buried the claw streaks, and every other strike is mirrored so a sustained attack does not stamp one slash. The pool is shared, and each slot sets its blending per burst, which is render state and recompiles nothing. Work ticks fire every 15 ticks per worker on any task, so their dust is capped at six alive. Every sheet loads asynchronously, and an event whose sheet has not arrived plays the spark.
