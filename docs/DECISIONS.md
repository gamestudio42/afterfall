# Architectural decisions

1. **Three.js over Babylon.js.** We need direct scene control, instancing and procedural geometry, not a full engine. Only one 3D library is used.
2. **Component-bag ECS instead of an ECS library.** Entities are plain objects with optional components. They are trivially serializable and fast enough for hundreds of agents. Archetype storage can be revisited if profiling demands it.
3. **Grid navigation (2 m cells) instead of a road graph for the MVP.** The procedural city is small (420 × 352 m, about 37k cells), so A* is cheap, and the same grid handles walls, gates and local movement. A road graph layer for long trips is planned with real maps.
4. **Shared distance field for hordes** instead of per-agent A*. Walls have a cost proportional to their HP, so hordes pick a breach point emergently, with no cheating spawns inside the base. The field is recomputed only when the grid version changes. Full recomputation is about 2 ms today. Region-local invalidation is a planned optimization for large maps.
5. **Global stock with physical storage nodes.** Each storage building holds its own stock, and workers physically carry materials from storage to sites. The HUD shows totals. Tower guards are resupplied abstractly.
6. **Renderer reads simulation state directly** (read-only) instead of copying snapshots. This is simpler and allocation-free. The command queue still enforces one-way mutation.
7. **No Web Worker yet.** The simulation costs well under 1 ms per frame — measured at 0.045 ms with a city, a squad and the task systems on a 25 entity map, and the render is the whole frame at 320 ms in a software renderer (see [PERF.md](PERF.md)). The core is DOM-free, so moving it to a worker later is mechanical, but it would free four hundredths of a millisecond and buy nothing.
8. **Time freezes while an event card is open or before a base is chosen**, so the player is never punished for reading.
9. **Units are drawn at life size.** They were drawn 1.9× for legibility at the strategic zoom, and that held while the units were capsules nobody compared with anything. Once the models read as people it stopped holding: a survivor stood 3.65 m tall against a 1.41 m car and a 3.2 m door module, so the city looked built for dwarves. The scale is now 1.0 and the default camera distance came down from 170 m to 120 m, which buys back most of the pixels the scale gave up — a unit is about 19 px tall at the map zoom instead of 25. Measured in a capture at 14 m: the shirt band is 70 px, against 64 px predicted for a 1.92 m figure, where the 1.9× version measured about 122 px.
10. **Real maps are imported in the browser, not by an offline tool.** The game is a static site on GitHub Pages, so the player's browser asks Overpass for one small area (400 to 600 m square) when they start, and keeps the answer in IndexedDB. One request per new game is light use of the public servers; nothing is fetched in bulk. Search uses Nominatim only on an explicit search.
11. **One building path for both map kinds.** Procedural rectangles and real footprints go through the same extruded-outline renderer. The grid stamps footprints by cell center; door, perimeter and window-fire code use the outline when there is one and the rectangle otherwise, so procedural balance is unchanged.
12. **Every real map gets a supermarket and a police station.** If the area has none, a mid-sized shop, office or warehouse near the center is promoted, because food and ammo depend on them.
13. **Pages from the `gh-pages` branch, with PR previews.** GitHub Pages serves a single site, so `main` is published to the branch root and each pull request to `pr-preview/pr-<number>/` in the same branch (`rossjrw/pr-preview-action`). The main deploy keeps that folder, and a closed PR removes its own. A fork cannot push to `gh-pages`, so it only uploads the built site; `pages-preview-fork.yml` on `main` publishes that artifact after the pull request head matches the run, and never checks out the fork.
14. **Commands are drained while time is frozen.** A pending event, a manual pause or a defeat stops the clock, but the command queue is still applied. Resolving an event is a command, so waiting for the next tick would deadlock the modal; applying commands without advancing the clock keeps the UI responsive and preserves determinism. Commands are discarded after defeat.
15. **The debug controller is development-only.** `window.__afterfall` is assigned only under Vite's `import.meta.env.DEV`, so the production bundle does not expose a mutable simulation handle. The Playwright suite runs against the dev server and keeps using the hook; CI rejects the string in `apps/web/dist`.
16. **Saves are validated before load.** `deserialize` rejects newer versions, malformed internals, OSM saves without their embedded map and states whose building count does not match the map. Imported maps must keep the same building order they had when saved, and migrations are added per version bump.
17. **Quality gates run in CI.** ESLint and Prettier check the code, Vitest enforces V8 coverage thresholds, `pnpm audit` blocks high or critical advisories, and a WebKit smoke test checks the shell beyond Chromium. Firefox smoke is available locally; the hosted runner lacks a Firefox WebGL context without extra OS packages.
18. **The Linux desktop build is a snap of the web game.** `apps/desktop` is an Electron shell that serves `apps/web/dist` from `app://game/` and adds only a quit bridge. The Snap Store builds `snap/snapcraft.yaml` on `main` and releases it to edge. CI builds the same file, installs it and runs `--smoke`, which starts a generated city and checks the HUD, local storage and the quit bridge. The smoke does not use `window.__afterfall`. Real-map downloads are allowed to reach Overpass and Nominatim; the rest of the game stays offline.
19. **Sound is a separate package driven by the simulation, never by the UI.** `@afterfall/audio` keeps the sound table and the event mapping pure (no DOM, no Three), and its director reads `sim.fx` and `sim.state.alerts`, so combat, construction and night alarms make noise without any component wiring sound by hand. The browser only unlocks an `AudioContext` on the first gesture and feeds the director once per frame. Voices are capped per sound and globally, and a backlog larger than a couple of dozen events is dropped instead of dumped, so a paused tab never returns in a burst of noise. Positional sound is approximated from the screen centre in world space (pan ignores camera rotation for now). Volume and mute live in the UI store and are persisted with the language (`afterfall.volume`, `afterfall.muted`); the director follows the store instead of the UI calling it. Day and night each get a looping ambience bed, crossfaded over 1.2 s when the clock changes half of the day.
20. **Impact effects are particles instanced from the same events as the sound.** `VfxSystem` reads `sim.fx` and turns each hit, death, melee, shot and build into a short-lived burst of billboarded quads in one `InstancedMesh` (one draw call; the particle is a radial gradient drawn to a canvas). Additive blending doubles as the fade — the instance colour runs to black as the particle ages, so no per-particle material or alpha sorting is needed. Physics uses a clamped step, but lifetime consumes the real delta, so returning from a background tab never leaves ghosts on screen.
21. **Each event has its own flipbook, and dull ones blend normally.** On top of the particles, a pool of 24 billboarded quads plays a flipbook per event: a muzzle flash for shots, a cloud for deaths, dust for work ticks, a claw slash for infected strikes, a ground ring for gunfire noise, a rubble cloud for a fallen structure, and the original spark for hits. Flash and spark are additive; the clouds are not, because adding a dark or dull colour adds nothing, so they use normal blending, fade by opacity and replace the particles of their event (twenty additive red particles glowed like neon over the death cloud). The strike is additive like the flash, but drops its particles as well: eight pale blobs buried the claw streaks, and every other strike is mirrored so a sustained attack does not stamp one slash. The strike's sheet was rebuilt once it was measured: with one camera and a paused simulation, the three thin strokes it started with owned 0.04% of the frame at the combat zoom and 0.01% at the default one — the least of the six atlas effects at both distances, on the event the player sees on every strike — so the sheet is now four thick staggered claws over an impact flash and embers, and it owns 0.21% and 0.03% with more than twice the contrast. The muzzle flash was measured the same way and rebuilt for the same reason: on every shot it owned 0.07% of the frame at the combat zoom, last of the seven, so its sheet went from two orange stars over a small core to a white-hot core with a six-point burst, a nine-point flare and a growing shock ring — six frames instead of four, and 0.16% with contrast 136. The `noise` event was declared but never emitted; `emitNoise` now publishes it with its radius (`Fx.r`), so the ring shows exactly how far a shot pulls infected. It plays no sound, because its shot already does, and without its sheet it draws nothing rather than a spark on every shot. A destroyed structure used to emit `death`, so a wall fell in a puff of blood; it now emits its own `collapse`, which is silent in the mapping because `alert.structureDestroyed` already plays. The pool is shared, and each slot sets its blending per burst, which is render state and recompiles nothing. Work ticks fire every 15 ticks per worker on any task, so their dust is capped at six alive. Every sheet loads asynchronously, and an event whose sheet has not arrived plays the spark.
22. **Facades are baked from geometry and multiplied under the building tint.** Each style is a 12.8 m module (4 bays by 4 floors of 3.2 m, the simulation's floor height) built in Blender with real recesses, frames, sills and boards, over 3 by 3 copies so shadows cross the tile edge, and rendered head-on in Cycles; grime is noise sampled on a torus, so the tile has no seam. The maps are kept near neutral because the vertex colour still carries game information (type, explored, looted, function, resource and danger overlays), and each style gets a gain that brings its mean up to the old concrete map, or the dark roofs went black at night. Night windows are one shared emissive mask per style gated by a per-vertex `glow`, set only on settlement buildings: the mask makes the city look inhabited, the gate keeps the rule that light means "ours". The art budget moved from 1 MB to 8 MB of streamed files because the maps load after the first frame and never delay a game's start.
23. **One infected model, three kinds, and only the skin is tinted.** `tools/blender/infected.py` bakes a single hunched silhouette (504 triangles, three materials) that the renderer instances in place of the capsule the infected had since phase 5; the capsule stays in the scene, hidden once the GLB lands, so a missing or broken file costs a silhouette and nothing else. The kinds are not modelled because the content table already separates them by `scale` and `color`, and a second and third mesh would be three more draw calls per part for a difference the player reads from size, speed and hue. The instance colour is written only on the `skin` part: giving every part an instance colour is the bug that turned the survivor kit's heads black, and here it would also multiply the emissive eyes to nothing. The eyes are the one emissive surface, which is what keeps a horde visible at night without a bloom pass. Measured in the headless renderer at 14 m: the model covers 5.6% of the frame where the capsule did, the frame is otherwise pixel-identical, and the whole horde costs three draw calls against the capsule's one. With 262 infected on screen the frame took 785 ms against the capsule's 923 ms over 20 frames each — inside the software renderer's own ±2× swing, so that is not a speed claim, only the absence of a regression. No separate silhouette per kind until a playtest says the kinds are not readable.
24. **Units walk on six baked poses, and the phase comes from distance travelled.** `InstancedMesh` cannot carry a skeleton, and one `SkinnedMesh` per unit would cost a draw call per survivor and another per infected, so the cycle is baked into the model instead: `tools/blender/survivors.py` and `infected.py` export `pose0`…`pose6`: six gait keys plus a standing pose, and the renderer keeps one instanced mesh per pose and material — 21 meshes per model, and only the poses that hold units this frame draw. The standing pose is not optional: with only the cycle, an idle unit froze on the contact pose and stood in a full lunge, 0.947 m deep against 0.491 m standing, which is what made a squad around the headquarters look wrong. A unit switches to it after eight frames without movement, which bridges the gap between 20 ms simulation ticks at 60 fps without flickering the pose. The phase is advanced by the distance a unit actually covered, not by a clock: a time-driven phase slides the feet as soon as the simulation speed or the frame rate changes, which is the exact artefact the animation is meant to remove, and a unit that has not moved stays on the contact pose so nobody marches on the spot. A jump longer than a stride in one frame is treated as a teleport and does not advance the phase. The first version drove the six poses with `sin(2πi/6)` and produced two distinct stances out of six, because `sin(60°) == sin(120°)`; the cycle is therefore an explicit table, and both exporters print each pose's foot positions and its maximum vertex distance from pose 0 so a future edit cannot quietly collapse the gait again. Measured 52 draw calls with the squad standing at the headquarters, 75 with thirty-three infected spread over the seven poses. The models grew from 21 KB to 123 KB (survivor) and 28 KB to 157 KB (infected).
25. **Research buys capabilities, and the laboratory is not gated behind them.** Twelve nodes in four branches, each one a capability the player can describe in a sentence (cheaper meals, a deeper well, a bigger pack, faster repairs, a workshop that doubles ammo, more loot per search, a deeper ammo reserve, better aim, floodlit towers, a one-dose serum, a faster lab, the cure). Points come from searching schools, hospitals, police stations, offices and pharmacies, and a standing **laboratory** earns them every game hour. The first version put the lab itself behind a seven-point node, which is a deadlock: the only reliable source of research was the thing the research was supposed to unlock, so a settlement that had not searched the right buildings could never start. The lab is therefore a plain conversion, and the `lab` node upgrades its output by half. Research is kept in `state.research` rather than in the stock: it has no weight, it is not hauled, and it cannot be lost with a warehouse. The cure costs 12 medicine and 12 research and then advances one dawn at a time while its lab stands — the endgame is a building the player chose to defend, not a timer, and losing it pauses the project instead of failing the campaign. The campaign runs twelve nights because that is where the measured curve still lets a walled settlement hold; the cure is the intended ending and surviving is the fallback. Measured: the scripted fort player wins 3 of 10 seeds with research and 2 of 10 without, which is inside the noise of ten seeds and is recorded as unresolved, not as a gain (see `docs/BALANCE.md`).

26. **Structures are modelled per kind and instanced per material.** The five built structures shared one box scaled by `STRUCTURES[kind]`, so a tower and a wall differed only in height and hue. `tools/blender/structures.py` authors each one to the footprint the simulation already uses, and the renderer keeps one `InstancedMesh` per material per kind, which costs fifteen draw calls at most and none for a kind that is not on the map. Two rules came out of it: metalness stays at 0.15 because three.js has no environment map here and anything metallic renders black, and walls and gates read their neighbours in the navigation grid to decide the quarter turn (`axialYaw` in `structureLayout.ts`), because a piece drawn across its own line reads as a row of slabs with gaps, and a gate drawn sideways is worse than the box it replaced. The construction ghost uses the same axis and the piece's own thickness, so what is being raised is legible before it exists. The old box is kept as the fallback and as the blueprint ghost: a missing GLB costs a silhouette, never the game.

27. **Wear is one merged mesh per map, and state reaches the street through it.** The city had clean asphalt, no debris and buildings that only changed colour when looted. Three layers close that gap without a texture per building: street wear (cracks, patches, oil, rubble, weeds through the kerb joints, drifted litter) generated as an 8-tile atlas by `tools/make-decals.ts` and merged into a single geometry with per-vertex UVs, so a map carries three thousand pieces of wear in one draw call; a building's state (picked clean, or taken over) which drives the tint, the debris at the doorstep and the sweep of it, rebuilt only when a signature of the settlement changes; and a flag on the roof of every building the survivors hold, in the colour of what it is for. Three things had to be got wrong first. The decals were wound clockwise, so the computed normal pointed down and backface culling ate the entire layer — the fix is pinned by a test that reads the normal back. The flag first hung at the foot of the wall, where a building swallows its own flag, and then edge-on to the street, where it was four pixels of nothing; it now stands above the roof edge, facing the street. And the settlement light sat at 6 m over a 3.8 m roof, turning that roof into a white plate at night. The prop kit grew a container, a pallet of crates and an ambulance, chosen by the block's zone rather than by a global dice roll, and the prop hash took the side of the block as an input after all four sides were found carrying the same objects.

28. **Reachability is answered before A\* starts.** A settlement that walls itself in makes a large share of destinations unreachable, and A* answered "no" by expanding the whole grid — once per unit, on every retry. A CPU profile of one campaign seed put 44% of the time in `findPath`, 41% in the binary heap it pops, and 8.5% in `passableIndex`. `NavGrid` therefore keeps connected components of its passable cells, one array per agent because survivors may cross a gate and infected may not, rebuilt lazily when the grid version changes; `findPath` compares the two components first and returns in constant time when they differ. The flood fill uses the same no-corner-cutting rule as the search, so it cannot disagree with it, and a unit test pins that a rejected pair really is unreachable and that a gate splits the two agents. The same seed went from 400 s to 13 s, which is what makes a sixty-seed balance arm practical.

29. **The campaign bot plays a plan, not a chain of ifs.** Three bugs had made the scripted player look strategy-less: the workshop was requested on the building the shelter had just taken (a conversion on a building with a task is refused silently, and the bot believed it had one for twelve days); a strict `if/else` chain meant "no searched building for a shelter yet" also skipped the towers; and `hp > 0` filtered out every candidate, because an unconverted building has `hp: 0` and `maxHp: 0` until a function gives it one. It now takes one structural decision per game hour, each step independent so a blocked one does not starve the rest, pays for what it queues, and lowers `keepAmmo` to 20 while a metal-hungry structure is still owed. The wall ring stays where it was — one blueprint two minutes in — because a version that placed it in affordable slabs lost every seed of ten: the blueprint is a queue that fills as wood arrives, so starving it buys nothing and delays the wall the first night needs. Measured over twelve nights and sixty seeds: 24 wins with the research tree and 25 without, every research win a cure and every plain win a survival, so the tree buys the ending rather than the survival.

30. **Task priority is a player lever, so it gets a drawer.** The assignment loop already sorted tasks by `priority` and the `setTaskPriority` command already existed, but nothing in the interface could change it, which made the ordering a designer's decision the player could not see. The bottom bar gains a Tasks drawer listing every task in the order workers take them, with the status, the crew and two arrows that move the priority by ten inside 0–100. It is the one panel that explains why a worker is on the farm while the wall sits half-built.

31. **Storage is a place, and a full store refuses the harvest.** Before this, every deposit went to the nearest store and whatever did not fit was dropped without a word: on seed 2 the headquarters reached 600 of 600 on day 8 and spent the rest of the campaign throwing its own harvest away, which the ledger could not show because `produce` never looked at what `deposit` returned. Production now counts what a full store refused into `stats.wasted` and `econ.wasted`, and raises `alert.storageFull` — the one piece of feedback that makes converting a building into a warehouse a decision rather than decoration. The ledger panel gained the column that shows it. The bot converts one warehouse once the headquarters passes 85%, which on that seed doubles the food it keeps (135 at day 7 instead of 292 then wasted, 1,103 by day 11). Hauling is the second half: a `haul` task carries the excess of a store above `policies.haulAbove` (90% by default) into one with room, in batches of 40, at the lowest priority in the queue so it never takes a hand from a wall. It fetches from its own source rather than the nearest store, and it deposits into the destination's shelves rather than onto its doorstep. One haul exists at a time; with two stores both full there is nowhere to haul to, and the answer is another warehouse, not another task.

32. **Clearing a spatial hash is a counter, not a sweep.** The hash kept every bucket it had ever created and `clear()` walked all of them, twice per tick, because buckets are never removed. That is fine for a few hundred agents in one skirmish and fatal for a twelve-night campaign: the map fills with the cells anything has passed through, and clearing them cost more than the queries the hash exists to answer — 44% of a CPU profile at day nine with twenty-eight survivors. Clearing is now a generation bump: a bucket from an older generation is treated as empty by `query` and claimed on its next `insert`, so `clear()` is an increment and the cost of a bucket is paid once, when it is used. The slow seed went from 54 s to 23 s, and a profile afterwards is flat — no function above 7.5% — which is the signal that the next win is structural (a worker thread, LOD, chunk streaming) rather than local.

33. **A large city could not be built at all, and streaming is deferred on measurement.** The roadmap carried "chunk streaming and LOD for large imported cities" as a performance item. Before designing either, the cost of a large map was measured, and the answer was not a cost: `BuildingBatch` concatenated its vertex groups with `push(...array)`, and spreading a few hundred thousand numbers as call arguments overflows the stack. Six blocks of city worked; ten blocks — 435 buildings, 43k triangles, smaller than a real imported neighbourhood — threw `RangeError: Maximum call stack size exceeded` inside the constructor. The merge now uses typed arrays and `set` with a running offset, with the `owner` array moving in triangles while the vertex arrays move in vertices. Measured after the fix, eighteen blocks by eighteen: 1,553 buildings, 845 ms to build on load, 19 draw calls, 132,884 triangles, 4.8 ms per frame under SwiftShader. That is a 1.2 km square with more buildings than the importer accepts (it stays under 600 m), and the draw-call count and frame time are flat from six blocks to eighteen. Streaming and LOD exist to bound a cost that is not there; what would justify them is a map an order of magnitude larger than the importer allows, or a GPU measurement this project still does not have.

34. **An imported map is a city, not a lawn.** The ground of every map was the grass map, which is right for a generated city — blocks with sidewalks, grass between them — and wrong for an imported one, which has streets and building footprints and nothing else. A dense neighbourhood therefore rendered as buildings standing on a lawn with thin paved ribbons along the roads, which is what the first playtest video showed. `buildCityGround` now reports whether the map is imported (`blocksX === 0`, the value `cityFromOverpass` writes) and shades its base with the concrete map under a neutral tint; parks keep their grass polygons. The same function used to crash outright on a map with no roads at all, because `mergeGeometries([])` reads `geometries[0].index` without checking — guarded now, and pinned by a test that builds a map with no roads.

35. **A sidewalk sits beside a road, never under it.** Imported streets were drawn as a road ribbon with a wider sidewalk ribbon underneath, five millimetres apart. That is invisible up close and unmaintainable at distance: the two surfaces are coplanar within the depth buffer's precision, so the light ribbon won alternating stripes across the asphalt — regular white dashes on the road that appeared and disappeared as the camera moved, which is what the second playtest video showed. Raising the road and biasing its depth helped, but the overlap was the defect: the sidewalk is now built as two strips beside the carriageway, and a test asserts that no sidewalk vertex falls inside the road's half-width. The base of an imported map has been paved since decision 34, so the strip is a light edge, not the only ground the player sees.

36. **A paved base has to be darker than its sidewalk.** Decision 34 paved the base of imported maps and got the material right but the value wrong: the tint was as light as the sidewalk, so every open lot read as pavement and a building beside a street looked like a building on top of it — which is exactly how the third playtest report phrased it ("os prédios estão sendo construídos até em cima da rua"). Measured before changing anything: on a live São Paulo import, 13 of 238 buildings touch a road corridor, none with more than 10% of its area inside one, and exactly one building sits inside another (a tower over its annex, which is real architecture, not a bug) — so the data was not putting buildings on the road. The base is now clearly darker than the sidewalk, and a test pins the relationship rather than the literal colour: the base's luminance must stay under three quarters of the sidewalk's, so a future tint cannot turn the city back into a plaza.

37. **A building that OSM draws twice is imported once, and a footprint on a street is not a building.** Two guards now run before anything is stamped. The first drops the smaller of a nested pair — OSM maps a tower and its annex, or a building and its part, as separate ways, and both were rendered, so the smaller volume's walls cut through the larger one's roof and out over the road; a test asserts the invariant (no footprint sits entirely inside a larger one) rather than a particular pair. The second drops a building whose footprint is more than 40% inside a street corridor: keep an overhang over the sidewalk, because that is what dense cities look like, but a building standing on the carriageway swallows the road the survivors walk on. Neither guard fires on the São Paulo Sé import (191 of 191 buildings survive), which is why they are guards and not a fix — and why `?feet=1` now outlines every footprint on the ground. A screenshot cannot say whether a wall covering the street belongs to a footprint covering the street, because from a low camera a tall facade hides the road behind it; the overlay answers it in the frame. It is rebuilt with every city: it lives in the scene, not in the city group, so the first version survived a new game and drew the old map's footprints over the new one's empty lots.

38. **A street is as wide as OSM says it is, and a footprint stops at the kerb.** The ribbon used to take its width from a table by road class — every residential street eight metres, every primary twelve — and in a dense centre that was metres wider than the street, so the asphalt ran into the lots and a footprint mapped exactly where OSM puts it read as a building standing on the road. That is the fifth playtest report, and the yellow overlay was what proved it: the outline sat at the wall's base, and the wall's base sat on asphalt. Width now comes from the `width` tag, then from `lanes`, then from the class; on a live Sé import that is 4.2 m to 20.2 m instead of a fixed table. And a footprint that still reaches into a carriageway is pulled back to the kerb — vertices pushed to the corridor edge, which is cheaper than clipping two polygons and keeps the shape — with a footprint that would lose more than 40% of itself dropped instead of mangled. A test walks every footprint vertex against every road segment and asserts none falls inside.
